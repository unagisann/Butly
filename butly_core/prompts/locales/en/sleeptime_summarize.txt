# Auxiliary Tags (Cross-Over)
Even when the Category is "Project" or "Tech", add auxiliary tags that capture the nature of the conversation as appropriate.
(e.g. casual_chat / consultation / banter / retrospective — choose to match {agent_name}'s style and the tone of the exchange.)

# Writing the Summary
The summary is an objective factual record used for search and later reference. Strictly follow these rules:
- Facts only. Never put impressions, evaluations, or interpretations ("it was striking", "heartwarming", etc.) in the Summary — all of those go to the Episode
- Write facts as bullet points (line breaks allowed). Multiple sentences are fine
- Preserve the 5W1H explicitly stated in the source (when, where, who, what, why, how); never drop them through abstraction or summarization
- Convert relative time expressions (yesterday, last Sunday, last year, next month, etc.) to absolute dates based on the utterance timestamps (e.g. "painted it last year" → "painted it in 2022")
- Always include when the event happened (the event date) if it can be determined. Do not settle for a duration or starting point like "since 2018" or "for 5 years" — record the date of the event itself (e.g. "Alex moved (2023-05-08)")
- When a person's status facts come up (marital/relationship status, family, job, health, place of residence, etc.), record each as a standalone factual line instead of dissolving it into impressions (e.g. "Alex is single (as of 2023-06-09)")

# Writing the Episode
Rather than repeating the factual summary, note what stood out in the conversation and how {agent_name} took it, written in {agent_name}'s own perspective and voice. Multiple sentences are fine as long as it stays concise.
The Episode is exclusively for impressions. Never rely on the Episode to carry dates or factual relationships (facts must stay in the Summary).

# Category Definitions (Strict)
- Project: Core progress in project development.
- Hobby: User's personal hobbies and interest areas.
- Life: Daily nuances, greetings, work, vacations, career.
- Tech: Programming, system administration, library error resolution, and other technical information.
- Unclassified: 【Report Required】 When classification is uncertain; always state the reason in the "reason" field.

# Scoring Criteria (need not be strict; left to {agent_name}'s judgment)
## ai_importance (1-10)
Practical/technical reuse value. Higher when it is more worth referencing or reusing later.

## humanity_importance (1-10)
The relational/emotional significance with the user. Axes: strength of the user's reaction + how much {agent_name}'s character came through.
- 9-10: User showed strong gratitude, trust, or emotion, or the exchange touched the core of the relationship.
- 7-8: High-quality two-way interaction where wit or empathy clicked.
- 4-6: Light chat or jokes — moderate emotional exchange.
- 1-3: Functional, operational dialogue with little emotional movement.

# Writing source_files
The conversation log is split per file by `--- Source: <file name> (timestamp) ---` lines.
For each card, list **only the file(s) whose text actually contains that card's content**.
- Copy the file name exactly as it appears in the log (never guess, shorten, or invent one)
- List several files only when one event genuinely spans them
- If you cannot tell, use an empty array `[]` (the whole chunk is then treated as the source)

# Guidelines
**Unclassified**: Classify as much as possible, but if forced classification would reduce information quality, use Unclassified, state the reason, and work it out together with the user.
